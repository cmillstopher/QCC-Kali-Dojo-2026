Make Kali Yours

Why script your setup?

Every pentester ends up with a handful of tweaks they redo on every box: the aliases they can’t live without, a prompt that shows the git branch, a folder layout for engagements. Typing them out each time is slow and easy to forget. A setup script fixes that:

  • Reproducible — a brand-new VM becomes your working environment in seconds.
  • Portable — the same script follows you to the next laptop, the next rebuild, the next range.
  • Documentation — the script is the record of how your box is set up.
  • Yours — start from someone else’s ideas, then bend it to how you actually work.
The golden rules of setup scripts.
  • Read before you run. Any script, including the two below. At a security event especially, less it first.
  • Back up before you change. Copy the dotfiles you touch, so you can always get back.
  • Make it idempotent. Running it twice should be safe and produce the same result, not a mess.
  • Personal config runs as you, not root. Keep sudo for the few steps that truly need it (installing packages).

The ideas

What people automate

These are the patterns that show up again and again in community setup scripts. Each is a few lines of bash.

Aliases & functions

Teach the shell your shortcuts

Aliases rename a command; functions do the things a rename can’t. A classic: pull the open ports out of an Nmap grepable file, ready to paste into the next scan.

alias ll='ls -lah --color=auto'
alias ports='ss -tulpn'          # what's listening on THIS box

# open ports from an nmap -oG file, as a comma list for  nmap -p
extractports() { grep -oE '[0-9]+/open' "$1" | cut -d/ -f1 | sort -un | paste -sd,; }
# extractports scan.gnmap  ->  22,80,443,445
A clearer prompt

Make the prompt work for you

The repos reach for zsh + Powerlevel10k. You don’t need all that: a few escape codes give bash a prompt that shows your user, path, git branch, and turns the marker red when the last command failed. (Capture the exit code first, in a PROMPT_COMMAND function.)

__rs_prompt() {
  local ec=$?                           # grab the exit code before anything else
  local c; [ "$ec" -eq 0 ] && c='\[\e[38;5;108m\]' || c='\[\e[38;5;167m\]'
  PS1="\u@\h \w ${c}\342\235\257\[\e[0m\] "
}
PROMPT_COMMAND=__rs_prompt
A tidy workspace

One folder shape for every engagement

Decide where scans, loot, notes, and screenshots live once, keep it as a template, and copy it per target. Future-you always knows where things are.

mkdir -p ~/engagements/_template/{scans,loot,notes,screenshots}

# mkt : clone the template and jump into it
mkt() { cp -r ~/engagements/_template ~/engagements/"$1" && cd ~/engagements/"$1"; }
Better defaults

Upgrade the everyday tools needs internet

Small quality-of-life swaps the community scripts love: bat (a syntax-highlighting cat), lsd (a prettier ls), fzf (fuzzy history search), ripgrep (fast grep). These are apt installs, so they belong in the home/internet script, not on the offline Dojo network.

sudo apt-get install -y bat lsd fzf ripgrep jq tmux
# note: on Kali, 'bat' runs as 'batcat'  ->  alias bat='batcat'
Dotfiles

Keep your config in version control

Once your .bashrc, .tmux.conf, and aliases are how you like them, put them in a git repo. Then “set up a new box” becomes “clone my dotfiles.” That’s really all the big setup repos are: someone’s dotfiles plus a script to place them.

Sample scripts

Two small, heavily-commented scripts to get you started. They’re examples to learn from and edit, not a finished product, open them up and make them yours.

kali-personalize.sh offline-safe

No internet, no root. Backs up your shell config, adds the aliases, functions, prompt, and workspace skeleton above, all in one managed file you can edit or remove. Safe to try right here on the Dojo.

Download kali-personalize.sh

kali-tools.sh home / internet

Installs an editable list of quality-of-life CLI tools with apt. Needs internet, so run it at home, not on the offline Dojo network.

Download kali-tools.sh

Download & run (on the Dojo, pull them from the village site)

# grab them
curl -O http://10.50.70.249/assets/scripts/kali-personalize.sh
curl -O http://10.50.70.249/assets/scripts/kali-tools.sh

# READ IT FIRST — every time, for every script
less kali-personalize.sh

# then run the offline-safe one and reload your shell
bash kali-personalize.sh
source ~/.bashrc
These scripts only change your account’s shell config and create folders in your home directory. They don’t touch the lab, other users, or the network. Read them and you’ll see exactly that, which is the habit worth building.

Make it your own

The best version of these scripts is the one you’ve edited. Change the aliases to your muscle memory, swap the prompt colors, add the tools you actually reach for, then save the whole thing in a dotfiles repo so your next fresh Kali is one git clone away.

Ideas here were drawn from community Kali setup scripts worth studying at home, among them Raikia/Kali-Setup, floyddc/Kali-Customization, Z3r0nom1/kali-customization, UCYBERS/setupkali, and the scripting work of tatanus. We took the ideas, not the code, and so should you: read widely, then write your own.
