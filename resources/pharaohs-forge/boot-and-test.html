Boot & Test Your ISO

You built (or picked up) a custom Kali Live ISO, now make sure it works. Use the VM path for the workshop unless a facilitator approves a spare-USB demonstration.

  1. The Forge
  2. ISO of Doom
  3. Boot & test

Recommended

Path A: test in VMware

  1. Keep your existing Kali VM unchanged. If you plan to modify it, take a snapshot first.
  2. In VMware Workstation, create a new VM and attach the generated Kali Live ISO as its CD/DVD boot media.
  3. Use a disposable VM with adequate RAM and disk. Don’t connect vulnerable lab guests to hotel Wi-Fi or any public network.
  4. Boot the VM and choose the Live boot option the ISO presents.
  5. Open a terminal and verify your selected tools:
command -v nmap
command -v tshark
command -v wireshark
command -v curl

nmap --version
tshark --version
curl --version

Some commands won’t apply to your mission. A missing command means the tool wasn’t included or the build failed, ask a facilitator before rebuilding.

Optional

Path B: write to a spare USB

Destructive operation. Writing an ISO to a USB erases the whole destination drive. Confirm the drive by its size and device name. Never use your only working Kali USB or a drive with files you need, and never a village loaner.
  1. Use a spare USB drive and an approved ISO imaging tool.
  2. Select the verified custom Live ISO as the source and the spare USB as the destination.
  3. Double-check the destination before you start the write.
  4. Boot a test machine from the USB using its boot menu, if permitted.
  5. Verify the desktop and selected tools. Don’t assume changes persist after reboot unless persistence was deliberately configured and tested.

USB boot settings differ by machine. If firmware settings or Secure Boot block booting, use the VM path rather than changing a personal machine’s configuration without permission.

Completion checklist

  • The ISO boots to a usable Kali Live environment.
  • The selected mission tools are present.
  • You can explain why each selected package is needed.
  • You know a non-persistent Live session may discard files and installed packages after reboot.
  • Testing stays within the authorized Red Sands training environment.
