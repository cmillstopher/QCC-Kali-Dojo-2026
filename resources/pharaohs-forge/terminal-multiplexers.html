Terminal Multiplexers

A multiplexer lets one terminal hold many shells, split them into panes, and keep everything running even when your connection drops. For offensive work that isn’t a luxury, it’s how you keep a long scan alive and your engagement organized. We’ll focus on tmux.

  1. The Forge
  2. Terminal multiplexers

What is a terminal multiplexer?

Normally, a shell lives and dies with its window: close the terminal, drop the SSH connection, or lose the VPN, and every program running in it is killed. A multiplexer breaks that link. tmux runs your shells in the background on the machine; your terminal simply attaches to them. Detach, and the work keeps running. Reattach later, from the same box or a fresh SSH session, and it’s all exactly where you left it.

It’s organized in three layers:

Why you’ll want one

  • Long jobs survive disconnects. Start nmap -p-, a hashcat run, or a reverse-shell listener, detach, and it keeps going even if your SSH or VPN drops or your laptop sleeps.
  • One screen, many tasks. Split panes to run a listener in one and work in another, or watch a scan while you read its output live.
  • An organized engagement. A window per target or per task (recon, web, notes) beats a dozen lost terminal tabs.
  • Pick up where you left off. Detach at the end of the day, reattach in the morning, your scrollback and running jobs are intact.
  • Pairing & teaching. Two people can attach to the same session and watch the same screen.
On a shared box, remember a detached session is still running. Don’t leave a noisy scan hammering a target after you walk away, and tidy up sessions you’re done with (tmux kill-session -t name).

tmux in 90 seconds

Start a named session, do your work, detach, come back:

tmux new -s ops        # start a new session called "ops"
#   ... run things, split panes, switch windows ...
# press  Ctrl-b  then  d   to DETACH (the session keeps running)

tmux ls                # list sessions
tmux attach -t ops     # re-ATTACH to it later
The one thing to learn: the prefix. Almost every tmux command is the prefix key, Ctrl-b, released, then one more key. So “Ctrl-b then c” creates a window; “Ctrl-b then %” splits a pane. Below, C-b means that prefix.

Cheat sheet

Sessions (the detachable unit)
tmux new -s NAMEStart a new named session.
C-b dDetach, leaving everything running.
tmux lsList running sessions.
tmux attach -t NAMERe-attach to a session.
C-b $Rename the current session.
Windows (tabs)
C-b cCreate a new window.
C-b n / pNext / previous window.
C-b 0…9Jump to window by number.
C-b ,Rename the current window.
C-b wPick a window from a list.
Panes (splits)
C-b %Split left/right (vertical divider).
C-b "Split top/bottom (horizontal divider).
C-b then an arrow keyMove between panes.
C-b zZoom a pane to full screen (toggle).
C-b xClose the current pane.
Reading output
C-b [Scroll/copy mode: arrows + PgUp/PgDn to look back, q to quit.
C-b ?Show every key binding (the built-in help).

A simple engagement workflow

  1. Start the session for the target: tmux new -s acme.
  2. Rename this window to recon (C-b ,) and kick off a full scan: nmap -p- -oA scans/acme $T.
  3. C-b c for a web window; C-b c again for a notes window (open your findings.md).
  4. In the web window, C-b % to split, run a tool on the left, watch its log on the right.
  5. Heading off? C-b d to detach. The scan keeps running. Later: tmux attach -t acme, and you’re right back in it.

Pairs perfectly with the engagement folder skeleton: a session per target, a window per task, a folder per target.

Make it yours

A few lines in ~/.tmux.conf smooth off the rough edges. Reload with C-b : then source-file ~/.tmux.conf, or just restart tmux.

# ~/.tmux.conf — a gentle starter
set -g mouse on              # click panes/windows, drag to resize, wheel to scroll
set -g history-limit 50000   # keep a lot more scrollback
set -g base-index 1          # number windows from 1, not 0
setw -g mode-keys vi         # vi-style keys in scroll/copy mode
# split with | and - (easier to remember than % and ")
bind | split-window -h
bind - split-window -v

The Kali Builder can auto-attach a tmux session when you open a shell, and Make Kali Yours shows how to keep configs like this in a dotfiles repo.

What about screen?

screen is the older multiplexer and is often already present when tmux isn’t. The ideas are identical, only the keys differ: its prefix is Ctrl-a. Quick map if you land on a box with screen instead of tmux:

Do thistmuxscreen
Start namedtmux new -s opsscreen -S ops
DetachC-b dC-a d
Reattachtmux attach -t opsscreen -r ops
New windowC-b cC-a c
SplitC-b % / "C-a | / S
Is it installed? Check with tmux -V. If it’s missing, it’s a one-line install, sudo apt install tmux, but that needs internet, so do it on your own Kali at home, not on the offline Dojo network. If a box only has screen, the map above gets you moving.
