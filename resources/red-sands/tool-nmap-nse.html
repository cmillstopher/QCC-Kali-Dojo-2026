Nmap & the Scripting Engine

The Network Mapper mission starts you with nmap -sV. This is the deeper companion: the scan types, how to aim and pace them, and how the Scripting Engine turns Nmap from a port lister into an enumeration tool.

  1. The Arsenal
  2. Nmap & NSE reference

What a scan is really doing

Nmap works in layers, and most flags just turn a layer on: host discovery (is it up?) → port scan (what’s open?) → service/version detection (what’s listening?) → scripts (what can I learn or confirm?). Knowing which layer a flag touches is how you read any command at a glance.

Scan types

FlagWhat it does
-sSSYN “half-open” scan, fast and the default when run as root.
-sTFull TCP connect scan, used automatically without root.
-sUUDP scan, slow, but the only way to see SNMP, DNS, etc. Pair with a port list.
-snPing sweep, host discovery only, no port scan. “What’s alive on this subnet?”
-PnSkip host discovery, treat the target as up. Use when a host ignores pings.

Aim, detect, pace

Which ports

-p 21,22,80,445      # specific ports
--top-ports 100      # the 100 most common (good default)
-p-                  # all 65,535 - thorough, slow, noisy

What's listening

-sV                  # service + version detection
-sC                  # run the "default" safe scripts
-O                   # OS detection (needs root)
-A                   # aggressive: -sV, -O, default scripts, traceroute at once

How fast (and how polite)

-T0 … -T5            # paranoid → insane; -T3 is normal, -T4 faster
On the shared lab boxes, keep to -T3 or lower and avoid -p- sweeps during busy periods, a hammering scan slows the target for everyone. Scan the target you were given, nothing else.

Save everything (it’s evidence)

-oN scan.txt         # normal, human-readable
-oX scan.xml         # XML - the format Metasploit's db_import wants
-oG scan.gnmap       # greppable
-oA scan             # all three at once, basename "scan"

Get into the habit of -oA on every real scan. You’ll want the XML later and the text now.

The Scripting Engine (NSE)

NSE is a library of ~600 scripts that run against open ports to enumerate, detect vulnerabilities, and more. Scripts are grouped into categories, call one category, one script, or a pattern.

nmap --script default "$TARGET"            # same as -sC
nmap --script "ftp-*" -p21 "$TARGET"       # all ftp scripts
nmap --script vuln "$TARGET"               # safe-ish vuln detection
nmap --script smb-os-discovery -p445 "$TARGET"
nmap --script http-enum -p80 "$TARGET"     # find interesting web paths
nmap --script-help ftp-anon                # read what a script does first
CategoryNature
safe / defaultWon’t crash or exploit. Run freely.
discovery / versionEnumeration, gather detail about a service.
vulnDetects known vulnerabilities. Mostly detection-only, but read each one.
auth / bruteTests credentials, can lock accounts. Gentle, volunteer-gated.
intrusive / exploit / dosCan disrupt or exploit a service. Demo-only on shared boxes.

Scripts live in /usr/share/nmap/scripts/; refresh the index after adding one with sudo nmap --script-updatedb.

A sensible default, annotated

sudo nmap -sS -sV -sC -T3 --top-ports 100 -oA nmap_$TARGET "$TARGET"
#        │    │    │    │    │                │
#        │    │    │    │    │                └ save all three formats
#        │    │    │    │    └ the common ports
#        │    │    │    └ normal timing
#        │    │    └ default safe scripts
#        │    └ version detection
#        └ SYN scan (root)

Read it top to bottom; note every open port and the product/version. That list is what you hand to Metasploit, or what feeds the Chamber’s enumerate phase.

The AI angle. Assistants can now turn “a stealthy version scan of these ports” into the exact Nmap command, or read a scan back and summarise it, handy, but you still need to know what -sS and vuln mean to catch a bad suggestion. See AI + Kali: what’s possible.
