Blending In: Anonymizing Kali

A fresh Kali install announces itself on every network it touches: a hostname of kali, a burned-in MAC address, a unique machine id. This page covers the practical ways to turn that down, what each one hides, and which ones even do anything on an isolated lab.

  1. The Forge
  2. Anonymizing Kali

What gives you away

Before changing anything, it helps to know what a network actually sees:

  • Your hostname rides along in DHCP requests and mDNS chatter. A box literally named kali stands out in any DHCP lease table.
  • Your MAC address is your network card's layer-2 identity. Its first half identifies the hardware vendor, and Wi-Fi devices broadcast it while scanning, so it tracks you across networks.
  • Your machine id (/etc/machine-id) is a unique per-install identifier. Every copy of a cloned image carries the same one until you regenerate it.
  • Your files carry metadata: screenshots embed timestamps and sometimes device info, documents embed author and software fields.
Scope and intent. These are standard professional OPSEC and privacy techniques: blending a test host into an authorized client network, protecting the tester's own identity, and keeping deliverables clean. They are not a way to evade authorization or dodge accountability. On the Dojo, you still stay on your assigned targets.

Everything below works on the lab: it’s relevant on any network, isolated or not, and ships with a default Kali install.

1 · Hostname works on the lab

Stop announcing yourself as "kali"

Pick a neutral, unremarkable name (workstation, laptop-01) that blends into a corporate network.

sudo hostnamectl set-hostname workstation
# then update the 127.0.1.1 line so sudo stops warning:
sudo sed -i 's/\bkali\b/workstation/g' /etc/hosts
hostnamectl                      # confirm

The change fully applies on your next login or reboot. On a network, your DHCP requests now say workstation instead of kali.

2 · MAC address works on the lab

Randomize your hardware identity

Two approaches. Use macchanger for a quick one-off change, or let NetworkManager randomize automatically for every connection.

One-off, per session (macchanger)

sudo ip link set eth0 down
sudo macchanger -r eth0          # -r = fully random
sudo ip link set eth0 up
macchanger -s eth0               # show current vs permanent
# restore the real one later with:  sudo macchanger -p eth0

Automatic, every connection (NetworkManager)

Create /etc/NetworkManager/conf.d/mac-randomization.conf:

[device]
wifi.scan-rand-mac-address=yes

[connection]
wifi.cloned-mac-address=random
ethernet.cloned-mac-address=random
sudo systemctl restart NetworkManager

random gives a new MAC on every connection. Use stable instead if you need the same device to look consistent to one network while still hiding your real address.

3 · Machine id works on the lab

Make cloned images unique

This one matters most when you hand out one image to many people, exactly like a village of identical Kali builds. Regenerate it so every booted copy is distinct:

sudo rm -f /etc/machine-id /var/lib/dbus/machine-id
sudo systemd-machine-id-setup                 # generates a fresh one
sudo ln -sf /etc/machine-id /var/lib/dbus/machine-id

For a Live ISO, do this with a build hook (next section) so the first boot of each copy generates its own id.

4 · Metadata works on the lab

Clean your evidence before you share it

Your report's screenshots and files can leak your username, device, and software versions. Strip that before anything leaves your hands.

exiftool -all= screenshot.png            # strip metadata in place
exiftool screenshot.png                  # verify nothing sensitive remains

This is part of finishing a report cleanly. See Document & Report.

Bake it into your image

Everything above can be pre-set in your custom build, so every machine boots already blended in. In your live-build config:

Install the tools (package list)

for pkg in macchanger libimage-exiftool-perl; do
  echo "$pkg" >> kali-config/variant-default/package-lists/kali.list.chroot
done

Ship a neutral hostname and MAC policy (baked-in files)

echo "workstation" > kali-config/.../includes.chroot/etc/hostname
# and drop your mac-randomization.conf into
#   includes.chroot/etc/NetworkManager/conf.d/

Regenerate the machine id on first boot (a hook)

# kali-config/.../hooks/live/9000-machine-id.hook.chroot
rm -f /etc/machine-id && touch /etc/machine-id

Package names shift between Kali releases: confirm with apt-cache search <name> before a build. macchanger and exiftool both ship with a default Kali install, so they’re already there on the Dojo images.
