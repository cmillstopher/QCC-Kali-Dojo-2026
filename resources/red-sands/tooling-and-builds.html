How Kali’s tools are packaged, how to pick and verify the right ones for a mission, and how those choices become a custom image. A conceptual guide, don’t make system-wide package changes on a loaner USB.

APT & package concepts

Kali uses Debian’s package-management ecosystem. APT works from configured repositories and package metadata. Before installing anything, know its source, purpose, dependencies, and whether it fits the mission.

apt --version
apt-cache search nmap      # find packages related to a term
apt show nmap              # read a package's metadata
dpkg -l | less             # list what's installed
For the event, avoid a full system upgrade or changing repository configuration. It’s slow and can break tools mid-session.

Verify tools before you use them

nmap --version
tshark --version
curl --version

Choose a small, mission-aligned tool set and confirm each tool is present and understood before you run it. More tools is not more insight.

Custom ISO & live-build

Kali’s live-build turns a folder of configuration into a bootable custom image, selected packages, baked-in files, and install answers. Treat a full build as an advanced, pre-event or volunteer-led activity in a disposable build VM.

  • Review the official build config and your changes before running a build.
  • Keep a record of package selections and configuration changes, the recipe is the documentation.
  • Build and test in a disposable VM before writing to removable media.
  • Never use the 10 attendee loaner USBs for image writing or persistence experiments.

A toolkit for the four-phase cycle

A starting toolkit organised by what you do with it. Everything here ships with a default Kali install, so it’s available offline on the Dojo, no downloads and no custom build required.

Discover & enumerate

nmap netdiscover arp-scan smbmap enum4linux-ng nikto gobuster wpscan \
  onesixtyone snmp whatweb wafw00f netcat-traditional

Validate

metasploit-framework exploitdb sqlmap hydra        # searchsploit ships with exploitdb

Capture & report

script tee sha256sum xfce4-screenshooter   # log terminals, save output, screenshot, hash evidence

Blend in / OPSEC (optional)

macchanger proxychains4 libimage-exiftool-perl

Package names shift between Kali releases, verify with apt-cache search <name> before a build. The Document & Report page explains the capture tools; Anonymizing Kali covers the OPSEC set.

ARM deployments

Kali provides images for selected ARM platforms, but the correct image depends on the exact board, revision, boot method, and supported features. Confirm current support from Kali’s official documentation before choosing an image, don’t assume one image works across all Raspberry Pi or other ARM models.
