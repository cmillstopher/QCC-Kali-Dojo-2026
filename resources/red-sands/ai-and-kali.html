A glimpse beyond the Arena

AI + Kali: What’s Possible

The tools you’re learning here, Nmap, Burp, Wireshark, Metasploit, are starting to grow an AI layer. This page is a tour of how that’s being used in real tools, today, mapped to the stations you’ve worked.

Idea only, none of this runs in the Village. We’re not wiring AI into any station; every mission here is yours to drive by hand, because the skills underneath are the point. Think of this as a map of where the field is heading, so the tools you just learned click into a bigger picture.

The pattern behind all of it

Almost every example below is the same shape: a large language model that can read a request in plain English, decide which tool to run, and read the tool’s output back, with a human reviewing each step. The connective tissue is increasingly the Model Context Protocol (MCP), an open standard that lets an AI assistant call external tools through a small local server.

Kali now ships pieces of exactly this stack. As of 2026, Kali’s repositories include an MCP “Kali Server” that exposes tools like nmap, gobuster, and nikto to an AI client, paired with Ollama (runs open-weight models locally) and 5ire (a desktop AI client that speaks MCP). In a published walkthrough, a local model was asked in plain English to TCP-scan a host on specific ports, and it drove nmap through that chain and returned structured results, entirely offline. (Cybersecurity News, March 2026)

Why “local” matters. Running the model on your own machine (Ollama) instead of a cloud API keeps client data, scan output, and findings off third-party servers, a real consideration for authorized engagements under NDA.

Real use cases, by station

Station 02 · Network Mapper

Natural language → Nmap

Instead of memorising flags, you describe the goal, “a stealthy version scan of these ports”, and the assistant proposes the exact nmap command, which you review before it runs. It can also read a scan back and summarise what’s interesting.

In the wild: tutorials wire shell_gpt to generate Nmap commands from English (Hacking Articles); the Kali MCP server drives nmap from a chat client (Cybersecurity News).

Deepen the manual skill first → Nmap & NSE reference.

Station 03 · Hackazon & the Web

AI-assisted web testing

The web proxy you use already has AI built in. Burp Suite Professional added Burp AI in 2025 with features like Explore Issue (follow-up analysis and PoCs for scanner findings), an Explainer that describes a highlighted cookie or header from a security angle, one-click recorded login sequences, and AI false-positive reduction for access-control checks.

In the wild: Burp AI ships in Burp Suite Pro 2025.2, with community AI extensions (Shadow Repeater, AI HTTP Analyzer) in the BApp Store; it can be switched off under Settings → AI. (PortSwigger)

Deepen the manual skill first → Burp Suite reference · Hackazon.

Station 02 · Packet Analyst

Ask your packets questions

LLMs are being pointed at capture files so you can ask “what hosts talked to the FTP server, and was anything sent in the clear?” and get an answer with the packets that back it, a fast triage layer on top of, not a replacement for, reading the stream yourself.

In the wild: “Local Packet Whisperer” runs pcap Q&A against a local model; the Wireshark community presented natural-language packet interaction at SharkFest ’25 (“Talk with Your Packets”); Wireshark MCP servers expose captures to AI clients.

Deepen the manual skill first → Wireshark & tshark reference.

Station 03 · The Hidden Chamber

AI as a research & triage partner

Where the Chamber has you move Discover → Enumerate → Validate, AI assistants are being used to suggest the next step: reading a service banner and proposing which Metasploit module to check, explaining a CVE, or prioritising which finding matters most. The human still runs, and is accountable for, every action.

In the wild: Nebula wraps recon/exploit tools behind an AI assistant; PentestGPT guides an engagement step by step; MCP servers now expose Metasploit itself to an LLM.

Deepen the manual skill first → Metasploit reference.

Across every station · Document & Report

From evidence to first draft

The write-up is where AI is most immediately useful and lowest-risk: hand it your scan logs and notes and it drafts the finding, observation, impact, remediation, in the structure of a real report, which you then correct and own. It turns a blank page into an editable draft.

In the wild: reporting assistants like Burp’s Report LM extension and general LLM workflows summarise tool output into finding write-ups; the same local-model stack above keeps that data on your machine.

Pair it with → Document & Report.

The catch: why skills still come first

Every serious write-up on these tools lands in the same place: AI suggests, you verify. That’s the exact ethic the Village is built on.

It’s confidently wrong

Models invent CVEs, flags, and commands. If you can’t tell a real finding from a plausible one, AI will happily hand you the plausible one.

Scope is on you

An assistant that can run tools can run them at the wrong target. Authorisation and scope are a human responsibility, not a prompt.

Evidence doesn’t change

A finding is still true only if you can reproduce it. AI can draft the report, but you capture the proof.

Data handling matters

Cloud models see what you paste. Local models (Ollama) are why the Kali stack above runs offline.

That’s why you learned to read the nmap output, follow the TCP stream, and check before you run. AI raises the ceiling for people who already have the floor, and the floor is what the Arena is for.
