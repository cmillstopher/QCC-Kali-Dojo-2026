Burp Suite

The web missions tell you to “send it to Repeater and tamper.” This is the deeper companion: how Burp sits between you and the app, how to keep it in scope, and the loop that turns a hunch into a confirmed finding.

  1. Hackazon
  2. Burp Suite reference

The one idea: an intercepting proxy

Burp sits between your browser and the web app. Every request stops at Burp first, where you can read it, change it, replay it, or let it through. That’s the whole superpower. You’re no longer limited to what the page’s buttons and forms let you send. Community Edition ships with Kali and covers everything in the Hackazon track; you do not need Pro.

Get traffic flowing

  1. Launch Burp (Applications → Web Analysis), accept the temporary project.
  2. Burp’s proxy listens on 127.0.0.1:8080. Point your browser at it, the simplest path is Burp’s built-in browser: Proxy → Intercept → Open Browser, which is pre-configured.
  3. Using your own browser instead? Set its proxy to 127.0.0.1:8080 and install Burp’s CA certificate (browse to http://burp → “CA Certificate”) so HTTPS doesn’t throw errors.
  4. Toggle Intercept off to browse normally while Burp records everything in HTTP history.

Set your scope first: every time

Before you poke anything, tell Burp what you’re allowed to touch. This keeps your testing, and any noisy tools, on the lab app and nothing else.

Target → Site map → right-click the Hackazon host → "Add to scope"
Then: Target → Scope → tick "Use advanced scope control" if you need to be precise
And:  Proxy/HTTP history → filter → "Show only in-scope items"
Scope is a safety control, not a convenience. With it set, you won’t accidentally fuzz another attendee’s target or an out-of-scope host.

The tabs you’ll actually use

TabWhat it’s for
ProxyIntercept and read live requests; HTTP history is your log of everything the app did.
TargetThe site map of every URL seen, and where you set scope.
RepeaterYour workbench, edit one request and resend it endlessly to test a single input. Where most findings are confirmed.
IntruderAutomates sending a request many times with varying values (wordlists, IDs). CE is rate-limited, so it’s slow but fine for small lab fuzzing.
Decoder / ComparerEncode/decode (URL, Base64, hex) and diff two responses side by side.
ExtensionsThe BApp Store, add community tools. (Kali’s Burp is CE; some extensions need Pro.)

The working loop for Hackazon

Map

Browse the whole app

With intercept off, click through Hackazon, log in, search, add to cart, view an order. Every page fills the site map and HTTP history. You’re building the list of inputs to test.

Pick a request

Send it to Repeater

Find a request with an interesting parameter (a search term, a product id, a profile field) in HTTP history → right-click → Send to Repeater (Ctrl+R).

Confirm

Tamper and read the response

In Repeater, change one thing and hit Send (Ctrl+Space). A single quote that breaks a query, an id that returns someone else’s record, a payload that reflects unencoded, that difference in the response is your evidence. Keep the request/response pair.

Widen (optional)

Intruder for the repetitive part

Need to try many IDs or a small wordlist? Send to Intruder, mark the payload position, load a short list, start the attack. Sort results by status code or response length to spot the outlier. Keep it small, CE throttles, and the box is shared.

Shortcuts worth memorising

Ctrl+RSend the selected request to Repeater.
Ctrl+SpaceSend the current Repeater request.
Ctrl+Shift+BToggle Base64 on the selection (in editors).
right-click → Engagement toolsDiscover content, find references, generate CSRF PoC.
