Station 03 · Volunteer Guide

The Hackazon Web App

Hackazon is Rapid7’s deliberately vulnerable online shop. This is your map of what’s wrong with it and how to confirm a capture, so you can steer attendees, recognise a real finding, and keep them in scope.

What it is, and why it rewards manual work

Hackazon is a full e-commerce app with several attack surfaces, the web UI, a REST API, SOAP/XML services, and AJAX. It was built partly to show that naive automated scanners miss things: it uses randomised paths, AJAX, and anti-automation tricks. So the lesson at this station is methodical manual testing with Burp, a scanner alone won’t do it justice.

Scope & care. Attendees test only the lab Hackazon instance a volunteer points them to. Keep automated tools gentle on the shared app (few threads, modest sqlmap --level/--risk), no destructive data changes, and no touching anything else on the network. It resets with the lab if it gets wedged.

Running the station

  • First win: point newcomers at a easy class, reflected XSS in the search box, an IDOR id-swap, or SQLi on a product id. Quick, visible, and it builds confidence.
  • Steer by interest: data-focused folks → SQLi (then sqlmap to dump a table); break-the-logic folks → IDOR / parameter tampering; API-curious → the REST/SOAP surface (XXE, auth).
  • Verifying a finding: they should be able to show the effect and hand you the request/response, data returned, the alert firing, another user’s record, the honoured tampered value. “A scanner said so” isn’t a finding; the reproducible evidence is.
  • Common stumbles: scanners come up empty (by design, push them to Burp and manual testing); sqlmap too aggressive on the shared app (dial --level/--risk/--threads down); XSS “doesn’t fire” (it was stored, view the page as another session).
  • Documentation: every finding gets the four-part write-up (observation / evidence / impact / remediation) and an OWASP class, same standard as the host challenges. The sample report shows the shape.
To confirm on your instance: the exact vulnerable parameters and paths shift between Hackazon versions, walk the app once yourself before the event and note the specific inputs for the easy wins so you can nudge attendees precisely.
